# Contributing

## Development

This is a single Go module (`github.com/mrc4tz/mrcatz-go-datatables`, Go 1.23+) with one package per concern:
`datatable` (core protocol), `memtable`, `gormtable`, `meili`, `httpdt`, `gindt`, `editorimg` and the `cmd/mrcatz` CLI.
The wire protocol and every package API are specified in **[DESIGN.md](DESIGN.md)** — read it before changing behaviour.

```bash
go test ./...      # unit tests (SQLite in-memory for gormtable — no setup needed)
go vet ./...
gofmt -l .         # must print nothing (gofmt -w . to fix)
```

**PostgreSQL tests** (relevance ranking, `pg_trgm`, joins) are skipped unless `MRCATZ_TEST_POSTGRES_DSN` is set. Each test
runs in its own throw-away schema:

```bash
docker run -d --rm --name mrcatz-go-pg -e POSTGRES_PASSWORD=pg -p 54399:5432 postgres:17
MRCATZ_TEST_POSTGRES_DSN="host=localhost port=54399 user=postgres password=pg dbname=postgres sslmode=disable" go test ./...
docker stop mrcatz-go-pg
```

**Scaffold build check** — compiles the code generated by `mrcatz make` against this repo's `gormtable` / `gindt`
(run it whenever you touch `cmd/mrcatz/internal/scaffold/templates`):

```bash
MRCATZ_SCAFFOLD_BUILD=1 go test ./cmd/mrcatz/internal/scaffold/
```

To try the CLI locally without installing it:

```bash
go run ./cmd/mrcatz make Product --path admin   # run from a scratch directory, or clean up with "remove"
```

Guidelines:

- **Wire compatibility is rule #1.** Query parsing, JSON bodies and error shapes must stay byte-for-byte identical to
  [`@mrcatz/datatable-server`](https://github.com/mrc4tz/mrcatz-js-datatables) so `@mrcatz/datatable-vue` keeps working
  unchanged. The JS tests (`packages/core/test`, `packages/server/test`) are the conformance suite — port new cases as
  table-driven Go tests.
- Please add a test for every new feature or bug fix, and keep `go test ./...`, `go vet ./...` and `gofmt -l .` clean
  (plus the PostgreSQL tests when you touch `gormtable` SQL or relevance).
- Keep dependencies minimal: `datatable`, `memtable`, `httpdt` and `editorimg` use only the standard library (plus the
  module's own packages); GORM is confined to `gormtable` (and `meili`, through it), Gin to `gindt`. No Meilisearch SDK
  — `meili` stays structurally typed.
- Exported identifiers are idiomatic English Go; code comments are in Indonesian (like the JS port).

## Releasing

Go modules are published by pushing a semver tag — there is no registry upload. While the Go port is in **beta**, releases
stay on `v0.x.y` (breaking changes allowed between minor versions); `v1.0.0` freezes the API.

```bash
go test ./... && go vet ./... && test -z "$(gofmt -l .)"
git tag v0.1.0
git push origin v0.1.0
```

Then make sure the Go module proxy has picked it up (this also triggers the fetch):

```bash
GOPROXY=https://proxy.golang.org go list -m github.com/mrc4tz/mrcatz-go-datatables@v0.1.0
```

The docs appear on [pkg.go.dev](https://pkg.go.dev/github.com/mrc4tz/mrcatz-go-datatables) shortly afterwards; if not,
open `https://pkg.go.dev/github.com/mrc4tz/mrcatz-go-datatables@v0.1.0` and click **"Request"**. Users install the CLI with
`go run github.com/mrc4tz/mrcatz-go-datatables/cmd/mrcatz@latest`, which resolves to the newest tag.

Tags are immutable on the proxy: never move or re-push a published tag — fix forward with a new patch version (or add a
`retract` directive to `go.mod` for a broken release).
